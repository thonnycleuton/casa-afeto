# ADR-003: Remoção da Entidade \"Cesta Concreta\"\n\n**Status:** Approved\n**Date:** 2026-10-19\n**Deciders:** Product Owner\n\n---\n\n## 1. Context\n\nO M2 (Cestas e Templates de Cesta) foi originalmente implementado com duas entidades de cesta:\n\n1. **Template de Cesta** (`BasketTemplate`) — molde reutilizável que define a composição padrão\n2. **Cesta Concreta** (`Basket`) — instância persistente criada a partir de um template\n\nO fluxo original era:\n\n```\nTemplate de Cesta → Cesta Concreta → Venda\n```\n\nA Cesta Concreta (`Basket`/`BasketItem`) existia como entidade independente no banco de dados, com CRUD completo via API, e era associada à Venda no momento da criação da venda.\n\n### Problema Identificado\n\nNão há caso de uso real para uma cesta persistida fora do contexto de venda. A Cesta Concreta:\n\n* Adicionava complexidade ao modelo de dados sem benefício operacional;\n* Criava uma camada intermediária desnecessária entre Template e Venda;\n* Exigia CRUD completo (criação, leitura, atualização, exclusão) para uma entidade que era apenas um passo intermediário;\n* Não era referenciada por nenhum outro fluxo de negócio além da Venda.\n\nNa prática, o operador cria um Template de Cesta e depois adiciona cestas diretamente às Vendas a partir do Template. Não há necessidade de persistir a cesta antes da venda.\n\n---\n\n## 2. Decision\n\nRemover a entidade \"Cesta Concreta\" (`Basket`/`BasketItem`) do projeto.\n\nRestam apenas **2 tipos de cestas**:\n\n1. **Template de Cesta** (`BasketTemplate`) — molde reutilizável, definido antecipadamente\n2. **Cesta da Venda** (`SaleBasket`) — cesta que existe apenas no contexto de uma venda\n\nO novo fluxo é:\n\n```\nTemplate de Cesta → Venda (SaleBasket)\n```\n\nQuando uma cesta é adicionada a uma venda a partir de um Template, a composição é registrada diretamente como `SaleBasket` + `SaleBasketItem`, sem intermediários.\n\n### O que foi removido\n\n* Modelo `Basket` e `BasketItem` no backend;\n* Serviço de cestas concretas (`backend/app/baskets/service.py` — ~150 linhas);\n* API REST de cestas concretas (`backend/app/api/v1/baskets.py` — ~81 linhas);\n* Schema `BasketRead`;\n* Frontend `BasketsView.vue`;\n* API client `baskets.ts`;\n* Testes de cestas concretas em `test_m2_baskets.py`, `test_cost_and_pricing.py`, `test_reference_price.py`.\n\n### Impacto na Personalização\n\nA personalização comercial acontece na **cesta da venda** (`SaleBasket`), não em uma Cesta Concreta. Quando uma cesta é adicionada a uma venda, o operador pode:\n\n* Alterar a composição (itens e quantidades);\n* Alterar o preço de venda;\n* Definir dados de entrega (destinatário, endereço, data, horário).\n\n---\n\n## 3. Consequences\n\n### Positive\n\n* Modelo de dados simplificado: de 3 tipos de cesta para 2;\n* Menos complexidade no CRUD: sem API de cestas concretas;\n* Menos código para manter;\n* Fluxo mais direto: Template → Venda;\n* Eliminação de uma camada de abstração sem valor de negócio;\n* A personalização de cestas continua funcionando via `SaleBasket`.\n\n### Trade-offs\n\n* O M2 foi originalmente aprovado com Cesta Concreta. A remoção requer atualização da documentação do M2;\n* Testes existentes que dependiam de `Basket`/`BasketItem` precisam ser removidos ou adaptados;\n* A migração de banco de dados precisa remover as tabelas `basket` e `basket_item` se já estiverem em produção.\n\n---\n\n## 4. Alternatives Considered\n\n1. **Manter a Cesta Concreta:** Rejeitado. A complexidade adicional não era justificada pelo caso de uso.\n2. **Cesta Concreta opcional:** Rejeitado. Manter a entidade como \"opcional\" ainda exigiria manutenção do código.\n3. **Remover a Cesta Concreta:** Selecionado. A simplificação beneficia mais do que prejudica.\n\n---\n\n## 5.
